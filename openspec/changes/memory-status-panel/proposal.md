## Why

`bundle-hindsight-runtime` turns the Hindsight Control Plane off by default. That is only defensible if errand can answer the questions a non-expert actually has, which today it cannot answer at all:

- Is memory working? Right now the only signal that Hindsight is misconfigured is that tasks quietly stop remembering things. There is no indicator anywhere in errand.
- Is it learning anything? A user who enables memory has no way to see that it did something.
- What is it costing me? Memory consumes LLM tokens on every retain and consolidation. That spend is currently invisible, which makes "my bill went up after I turned this on" impossible to investigate.
- What does it know about me? There is no way to browse or export what has been stored.

Hindsight's REST API already answers all of these. The gap is that errand never asks.

Crucially, `hindsight_url` and `hindsight_token` are server-side secrets — the token is generated by errand as of `bundle-hindsight-runtime`. The browser must never see either, so this cannot be a frontend-only change; it needs a thin proxy.

### Why this does not need the Control Plane

Mapping what the Control Plane offers against what a non-expert needs:

| Question | Endpoint | Audience |
|---|---|---|
| Is it up? Is its LLM reachable? | `/health/live`, `/health/ready`, `POST /banks/{b}/health/llm` | everyone |
| Is it learning? | `/banks/{b}/stats`, `/stats/memories-timeseries` | everyone |
| What failed? | `/banks/{b}/operations?status=failed` | everyone |
| What is it costing? | `/banks/{b}/llm-requests/stats` | everyone |
| What does it know? | `/banks/{b}/memories/list`, `/knowledge-base/export` | everyone |
| Entity graph, per-memory editing, directives, webhooks | `/entities/graph`, `/graph`, `/directives`, `/webhooks` | experts |

Only the last row justifies a second web application. Everything above it is a settings card.

## What Changes

- Add a server-side proxy under `/api/memory/*` that calls Hindsight using the server-held URL and bearer, and returns only non-secret data. The Hindsight URL and token SHALL NOT appear in any response.
- Add a Memory settings card showing: health and version, an LLM reachability check, counts and a memory-growth sparkline, failed operations with their error and retry state, token spend over a period, and links to browse or export what has been stored.
- Enable `HINDSIGHT_API_ENABLE_BANK_LLM_HEALTH=true` on the bundled Hindsight service, because the bank LLM health check is disabled by default and returns `"Bank LLM health check is disabled"` otherwise.
- Present Hindsight's taxonomy in errand's own vocabulary rather than exposing `world` / `experience` / `observation` fact types raw.
- Degrade gracefully using `/version`'s feature flags: hide the token-spend panel when `llm_trace` is false, and the failed-operations panel when the deployment does not report the corresponding feature.

## Capabilities

### New Capabilities

- `memory-status-api` — the server-side proxy: which upstream endpoints are exposed, what is stripped, how failures and absence of configuration are represented, and the polling contract.
- `memory-status-ui` — the settings card: what it shows, how it degrades, and what it must never render.

## Non-goals

- Editing memory. This card is read-only apart from an explicit re-check action; per-memory editing stays in the Control Plane.
- Replacing the Control Plane. It remains available behind its profile for graph exploration and the expert surfaces.
- Configuring Hindsight. `hindsight_url` is a deployment fact and is env-var-backed in every bundled deployment, so it is displayed read-only, not edited here.
- Per-task memory attribution. Tagging retains with the originating task id is a separate, smaller change against the memory system skill.
