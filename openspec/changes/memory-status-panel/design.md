## Context

Hindsight exposes a large REST surface. This change selects the subset a non-expert can act on, proxies it, and renders it as one settings card. Endpoint shapes below were read from the Hindsight OpenAPI document and verified against a running instance.

## Decisions

### D1 — Server-side proxy, never a direct browser call

`hindsight_url` and `hindsight_token` are server-held; the token is generated by errand and masked on read. A frontend calling Hindsight directly would require handing the browser a bearer that errand deliberately never returns. So the card talks only to errand, and errand talks to Hindsight — the same shape already used for the Slack bot token and `mcp_api_key`.

The proxy strips anything that could leak topology: no upstream URL, no bearer, no upstream error body containing either.

### D2 — Polling cost differs sharply per endpoint

Under the single-database decision from `bundle-hindsight-runtime`, Hindsight shares errand's PostgreSQL. A careless poll becomes load on the database errand itself runs on.

| Endpoint | Cost | Treatment |
|---|---|---|
| `/health/live` | no I/O — answering is the check | safe to poll |
| `/health/ready` | acquires a pooled connection, runs `SELECT 1` | poll sparingly |
| `/banks/{b}/stats` | accepts a `refresh` query parameter, implying a materialised cache | fetch on card view / explicit refresh only |
| `/banks/{b}/health/llm` | performs a real LLM round trip | explicit user action only, never automatic |

The card therefore polls only the cheap liveness endpoint; everything else loads on view or on an explicit refresh. The LLM check is a button, because it spends tokens.

### D3 — Bank-parameterised from the start

errand ships a single bank (`errand-tasks` by default), but `/v1/default/banks` returns a list with per-bank `fact_count` and `last_write_at`. Proxy routes take the bank as a parameter from day one so that per-user or per-profile banks later need no reshaping, even though the UI shows one.

### D4 — Translate the taxonomy, do not expose it

`nodes_by_fact_type` splits into `world`, `experience` and `observation`. Those are Hindsight's internal model. The card renders errand's own words — what it learned, what it did, what it noticed — so that adopting a different memory backend later would not require re-teaching users a vocabulary.

### D5 — Feature-flag driven degradation

`GET /version` returns a `features` object (`llm_trace`, `audit_log`, `worker`, `bank_config_api`, `observations`, …). The card asks rather than assumes, so a deployment pointing at an older or differently-configured Hindsight hides the panels it cannot populate instead of rendering errors.

### D6 — The LLM health check must be enabled explicitly

`POST /v1/default/banks/{bank}/health/llm` returns, by default:

```json
{"detail": "Bank LLM health check is disabled. Set HINDSIGHT_API_ENABLE_BANK_LLM_HEALTH=true to enable."}
```

This is the single most valuable endpoint for the target audience — it converts "memory silently does nothing" into a red dot with a reason — so the bundled service sets the flag. When the flag is off (an externally-managed Hindsight), the card shows the control as unavailable rather than reporting a failure.

## Endpoint selection

Proxied:

```
GET  /health/live                                  status, version, uptime
GET  /health/ready                                 database reachability, pool pressure
GET  /version                                      api_version, feature flags
POST /v1/default/banks/{b}/health/llm              explicit LLM reachability check
GET  /v1/default/banks/{b}/stats                   counts, last write, last consolidation, failure counts
GET  /v1/default/banks/{b}/stats/memories-timeseries  growth buckets
GET  /v1/default/banks/{b}/operations?status=failed   task_type, error_message, retry_count, next_retry_at
GET  /v1/default/banks/{b}/llm-requests/stats      token spend by period
GET  /v1/default/banks/{b}/memories/list           browse and search
GET  /v1/default/banks/{b}/knowledge-base/export   markdown bundle
```

Deliberately not proxied: `/entities/graph`, `/graph`, `/directives`, `/webhooks`, per-memory mutation. These are the Control Plane's remaining reason to exist.

## Risks

- **Proxy becomes a general-purpose tunnel.** Mitigated by enumerating allowed upstream routes explicitly rather than forwarding a path parameter.
- **Export size.** `/knowledge-base/export` returns a markdown bundle whose size is unbounded. It should stream or be size-capped rather than buffered into a response.
- **Stats cost under the shared database.** If `/stats` proves expensive on a large bank, the card's on-view fetch is the wrong default and it should move behind an explicit refresh.

## Open Questions

- Where does the card live in settings navigation — beside the existing MCP/skills cards, or under a new Memory grouping that would also host a future bank selector?
- Should the export be offered at all in the first iteration, given it is the one unbounded response in the set?
